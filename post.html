把个人主页当成一个长期项目

2026 年 10 月 12 日 约 6 分钟阅读 前端 · 设计

这个页面第一次上线是在三年前，期间换过四套模板、两次配色，也彻底删库重来过一次。 现在它终于只是这个文件树里的一些 HTML 和一份样式表 —— 我觉得这才是它该有的样子。

为什么最后是自己写

模板生成器的效率毋庸置疑：选一个主题、填几行配置，十分钟就能得到一个看起来还不错的站点。 问题出在第二年。当我想改一处间距、给列表加一个字段，或者让文章页有自己的排版时， 我发现自己一直在和别人的抽象层较劲。

一个页面的复杂度，应该和它的内容成正比。个人主页的内容很少， 所以它值得的复杂度也很低。

于是我把整个站点压缩成了三样东西：一份样式表、一个几十行的脚本， 以及若干个语义清晰的 HTML 文件。没有构建步骤，没有依赖，双击就能打开。

框架里有什么

现在这套骨架只做四件事，其余的都留给内容：

  • 设计变量：颜色、间距、圆角、字体全部集中在一处，改主题只动十行。
  • 可复用组件：按钮、卡片、标签、文章列表，都是纯 CSS 类名。
  • 渐进增强的交互：明暗主题、移动菜单、滚动出现的动画，脚本失效也不影响阅读。
  • 排版基线：文章页的标题、引用、代码块、表格都有现成样式。

比如，一个作品卡片在 HTML 里就是这样：

<article class="card">
  <div class="card__top">
    <span class="card__index">01</span>
    <span class="card__arrow" aria-hidden="true">↗</span>
  </div>
  <h3 class="card__title">
    <a class="card__link" href="https://example.com">作品名称</a>
  </h3>
  <p class="card__desc">一句话说明它解决了什么问题。</p>
</article>

几个刻意的选择

我放弃了把所有页面塞进一个 index.html 的做法。单页很酷，但文章需要独立的 URL， 分享出去才有意义。也放弃了自动生成，因为文章数量少到可以手动维护， 而手动维护的代价远小于调试生成器的代价。

选择 原因
手写 HTML 结构一眼看清，改起来没有中间层
原生 CSS 没有编译，也没有版本升级的焦虑
极少量 JS 增强体验，而不是支撑内容

如果你也想搭一个自己的站点，我的建议是：先写下你想放上去的那三件事， 再决定用什么工具。大多数时候，答案会比想象中简单。
